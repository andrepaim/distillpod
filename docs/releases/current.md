DistillPod 0.22.0-alpha.1 gives voice questions the available transcript from the beginning of an episode up to your listening position, with a prompt designed for more natural explanations.

- **Ask about earlier ideas:** the former two-minute and 12,000-character cutoffs are removed. Each question sends all available valid completed transcript segments up to the captured listening position in chronological order. Future or partially heard segments, invalid timestamps, and other audio revisions are excluded. Missing transcript passages are not invented or automatically transcribed.
- **Get explanations and examples:** the voice prompt now explicitly allows general knowledge, analogies, comparisons and reasoning without a routine restricted-context preface. Claims about what a speaker said, quotations and timestamps must still be grounded in the supplied transcript. Answers remain brief, in the question's language, and limited to one interaction.
- **Send context before recording:** the transcript is sent separately from instructions in bounded, Unicode-safe parts. Recording starts only after every part is acknowledged. Automatic provider truncation is disabled; recognized context-capacity errors explain that an earlier listening position may be needed rather than silently discarding the beginning. There is no automatic paid retry or summarization fallback.
- **Understand the cost and scope:** voice settings now state that questions and the available transcript up to your listening position go to OpenAI using your API credits. Longer transcripts consume more input credits. The existing model, encrypted key storage and voice opt-in requirements remain unchanged.
- **Production troubleshooting guidance:** the repository now documents an evidence-based error-triage workflow. This documentation does not add monitoring, uploads or scheduled device work.

Install the signed APK as an update **without uninstalling**. Version code **40** supersedes code 39 and retains the application ID and signing identity. Database schema 11, portable backup schema 7, Firebase protocol/rules and sync scope are unchanged. Older backups remain importable; new exports still require an app supporting schema 7. Paid content sync remains disabled, and voice preview remains enabled with its existing setup requirements. The matching GPL source archive, component manifest and notices accompany the APK.

**Known alpha limitations:** full context means the available completed transcript, which may be partial or have gaps. Existing current-audio, source, stale-state and 15-second coverage requirements still apply. Missing or insufficiently recent context can still pause playback and show the generic readiness error tracked in [#57](https://github.com/andrepaim/distillpod/issues/57); that separate fix is not included. Large transcripts remain subject to provider capacity, setup timeouts and network conditions. Live answer phrasing, actual provider capacity behavior, billing and long-context latency have not been measured with a live request. The prompt encourages natural, accurate answers but does not guarantee their quality. Existing storage, background, diagnostics and YouTube limitations from [0.21.0-alpha.1](https://github.com/andrepaim/distillpod/releases/tag/v0.21.0-alpha.1) remain.

The full scope is [all changes since 0.21.0-alpha.1](https://github.com/andrepaim/distillpod/compare/v0.21.0-alpha.1...v0.22.0-alpha.1): merged PRs [#55](https://github.com/andrepaim/distillpod/pull/55) and [#65](https://github.com/andrepaim/distillpod/pull/65). Automated coverage includes transcript selection, database snapshots, Unicode-safe transport, matching acknowledgements, cancellation and recognized capacity errors. An isolated Android 16 / API 36 emulator verified all 360 completed passages in a long partial transcript reach a fake provider before synthetic recording, while excluding wrong-revision and future speech. This establishes payload and protocol behavior, not live model performance. Release publication is gated by the exact candidate's Android CI and signed-build verification. The scoped change does not alter microphone/audio routing, Bluetooth, permissions, playback leases, background scheduling or upgrade persistence; no new physical-phone validation or owner-data upgrade is claimed.
