DistillPod 0.24.1-alpha.1 improves download recovery, queue playback and account recovery, and fixes a headphone-voice service shutdown that could crash the app.

- **Recoverable background-download refusals.** Episode and model downloads retry when Android refuses their foreground-service start. If the bounded attempts are exhausted, the download pauses with a message asking you to open DistillPod and resume. Partial files and resume information are retained. Other failures before a transfer begins are marked failed instead of leaving a queued row without work.
- **Pause while waiting.** Pausing a queued download now persists even before its worker starts, including during network or retry waits. Restarting the app does not automatically resume a deliberately paused download. System stops are distinguished from app cancellation so unfinished work can remain queued for Android to reschedule.
- **Safer headphone-voice shutdown.** If a voice-service start reaches the app after its key is missing, the service now completes Android's required foreground promotion before stopping, avoiding the reproduced early-return crash.
- **More useful, content-safe crash diagnostics.** Foreground-service failures receive an allowlisted service category and, for start timeouts, an indication of whether Android recorded the start call site. Raw service messages and class names remain redacted. This does not identify or claim to fix the original unidentified 0.23.0 foreground-service incident.

- **Clearer queue, smoother enqueue.** Time remaining for the current episode uses the player duration across listening views. Finished items show “Played,” and the queue groups its existing order into History, Now playing and Up next, initially focusing the current item. Adding or moving an episode uses incremental playlist commands instead of rebuilding and re-preparing the playing item. Compact/drag/swipe row actions and preservation of measured duration across feed refreshes remain separate follow-ups.
- **Safer account and API recovery.** Concurrent token refreshes preserve newer sign-ins, and only a matching explicit invalid grant disconnects the current credential. An unauthorized request gets one refresh/retry; access denial, quota exhaustion and temporary service errors have distinct recovery paths. Rejected temporary rate-limit requests get bounded retries, without replaying partially delivered streams. Long waits, process termination and errors after streaming begins can still require a manual retry.

- **Automation follows meaningful changes.** Show preparation no longer wakes its coordinator for playback-position or transfer-progress updates alone. A job needing user attention no longer blocks later eligible episodes, while actively running work remains serialized. The show page identifies blocked jobs and retains Retry preparation. Stage updates preserve job order and do not recreate removed jobs. This is not a measured battery-life claim.

Install the signed APK as an update over your existing DistillPod installation. Version code **46** retains the application ID and signing identity. Database schema 12, portable backup schema 7, Firebase protocol, rules and distribution configuration are unchanged. The voice preview remains enabled, and automatic cleanup remains disabled. No backend deployment is required.

Validation includes regression tests for download rejection, pause/recovery and service diagnostics. Test-only corrections wait for the current transfer to write bytes and for the selected library filter/list reset to settle before UI scrolling; original acceptance assertions are retained. Publication requires full hosted validation of the release candidate, successful exact-source main validation and the release workflow.

**Device evidence and limits:** isolated Galaxy S22 / Android 16 builds demonstrated background refusal/retry exhaustion, persistent pause, partial-download Resume and the voice missing-key crash before and after the fix. The corresponding production code is unchanged from those tested revisions. Separate isolated S22 tests covered Play next while playing on the actual playback service, and offline synthetic account-vault/Keystore reopening and connection-state behavior. These do not establish exhaustive queue/Bluetooth coverage or a live provider/account test. Automation device evidence used synthetic transcript-progress and playback-checkpoint writes, not real Whisper decoding or audio playback; the original idle incident and live Resume/sign-in recovery were not reproduced. The owner installation was not changed. Real system/long-running foreground timeouts, notification Pause and model downloads were not physically exercised; those paths rely on automated evidence. The original cold-process download trigger was approximated by a background retry. No signed upgrade on the owner's installation or live cross-device test is claimed. Android may still require you to open the app to resume downloads.

Bulk audio cleanup, automatic retention, local transcript deletion and the ChatGPT integration remain unfinished and are not included.
