DistillPod 0.17.0-alpha.1 adds optional cloud diagnostics so failures during listening can be investigated without retrieving Android logs over USB.

- **Share diagnostics:** enable it in **Settings → Diagnostics**. Collection defaults off and is separate from library sync or account sign-in. Reports include app/build identity, operation stages, safe failure categories and network state. Audio, transcripts, questions, answers, podcast URLs and credentials are excluded from the application event fields; exception details are sanitized before upload.
- **Useful bug reports:** choose **Copy diagnostic reference**, then describe approximately when the problem happened, which button/action you used, what you expected and what happened. The reference allows earlier sessions to be found remotely. **Send test diagnostic** sends a synthetic log and a harmless handled error; it does not crash the app or make an AI request.
- **Listening diagnostics:** events cover received headphone commands and mapping/debounce decisions, saving moments, transcript preparation and network/power waiting conditions, distillation outcomes, playback errors, voice-session outcomes and selected sync/background failures.
- **Offline delivery:** a bounded private queue retains pending reports for up to 72 hours and uploads when internet is available, including mobile data. Turning diagnostics off clears pending reports. Previously transmitted reports remain subject to Sentry retention/deletion controls.

Voice preview and existing headphone preferences are retained. This update preserves the application ID, signing certificate and Firebase configuration; there is no library database, backup-format or sync-protocol migration. Paid content sync remains disabled. Install as an update without uninstalling. Android 10+; ARM64 and x86_64. Version code **34** supersedes published/private code 33.

Diagnostics are best effort. Android may delay background uploads; force-stopping the app prevents work until it runs again. Queue/collection limits and abrupt termination can leave gaps. A missing headphone event cannot prove whether Android delivered a press. This alpha covers managed Android error reporting; native Whisper crash reporting, complete operation reconciliation and aggregate reliability dashboards remain future work. No session replay or screen recording is collected.

Validation includes 416 JVM tests, 22 tooling tests, debug/release lint and builds, plus S22 cloud log/handled-error receipt with readable stack frames and offline queue survival across process restart. Physical candidate checks used code 33 before the release metadata bump; the signed code-34 artifact is verified separately. The release workflow additionally requires exact-commit main CI, configured release checks, retained-signature signing and APK verification. Earlier physical car/headset trials do not establish this revision's real-world reliability.

See [cloud diagnostics](https://github.com/andrepaim/distillpod/blob/v0.17.0-alpha.1/docs/android/cloud-diagnostics.md) for event coverage, delivery limits and privacy controls.
