DistillPod 0.25.0-alpha.1 adds reviewed bulk audio cleanup, a more compact Saved collection, and improvements to playback progress, sync recovery and privacy.

- **Review and clear local audio.** In Settings → Storage, “Clear all local audio” previews completed downloads, unfinished downloads and other managed audio cache before confirmation. Only the reviewed selection is eligible. Playing, queued, processing and automatically preparing audio is protected; new or changed files are kept. Transcripts, saved insights, models and listening progress are retained. Cancellation stops after the current item, and partial results are reported honestly. Already deleted audio cannot be restored by cancelling; a retry requires a new review.
- **A clearer Saved collection.** Moments and Posts have their own tabs, with compact moment cards and a scrolling search field. A saved moment puts Replay, Share and Copy first, with other actions in More actions and source/previous-version details in expandable sections. Deleting a saved moment now asks for confirmation. Existing preparation and recovery actions remain available; unreadable history snapshots no longer crash the page.
- **Less repeated playback work.** Continuous playback is saved about every ten seconds rather than every second. Pause, seek, item departure and other boundaries still save their exact position. Service observers and library filtering avoid unrelated progress-only work. If the process abruptly dies while continuously playing, resume may be roughly ten seconds earlier; the In progress listing can lag by a similar interval. These changes are not a measured battery-life guarantee.
- **More useful sync recovery.** Temporary Firestore unavailable/deadline errors show “Waiting for a connection.” Deterministically refused cloud changes are set aside so later changes can proceed, with a visible count and Retry/Discard controls. Discarding a refused upload does not delete its local content, but permits newer cloud changes to apply. Sync triggers are coalesced instead of repeatedly chained; Sync now bypasses debounce and can replace work waiting in retry backoff. Android's connectivity and background scheduling restrictions still apply.
- **Privacy and smaller reliability fixes.** Android Auto cover images are no longer readable by arbitrary apps; accepted library browsers receive read access only to handed-out artwork. Unchanged periodic refresh configuration no longer resets its work, cancelled refresh-all stops promptly, and storage-quota errors point to the relevant Storage controls.
- **Microphone recovery.** A denied voice microphone request offers Open app settings, including after Android stops showing the permission prompt. A granted microphone without a saved API key routes to Voice settings instead of displaying a microphone error.

The intended signed update uses version code **47**, preserving the application ID and signing identity. Database schema 12, portable backup schema 7 and cloud protocol/rules are unchanged. Voice preview remains enabled; content uploads and automatic audio retention remain disabled. No backend deployment is required.

**Validation status:** this is release preparation, not a published APK. Fresh release-candidate checks and exact merged-main/publication validation remain required. Physical validation of the changed sync scheduling/backoff behavior is still missing and blocks publication. Existing isolated Galaxy S22 evidence covers bulk cleanup protection, playback checkpoint measurements and the microphone-settings round trip on the corresponding unchanged code; it does not establish the missing sync scheduling behavior. Android Auto artwork grants have emulator coverage, not a real car-host/DHU check. No owner-app upgrade, live-account sync or battery-life measurement is claimed. Test-only diagnostics fixtures isolate host preference fsync while retaining real XML writes and semantic assertions; they do not prove physical durability.

Local transcript deletion/suppression, automatic retention, sleep timer, measured-duration retention across feed refresh, sync snapshot caching and the ChatGPT integration are not part of this candidate. Sync's remaining deterministic refusal and restore/query-locator improvements are separate work. A failed sync chain can still need another trigger or periodic recovery; backoff replacement retains a narrow start race.
