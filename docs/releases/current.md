DistillPod 0.37.0-alpha.1 keeps transcripts and downloads going when Android refuses their notification in the background, says why a queued transcript is waiting, and fixes diagnostics uploads that arrived days late.

- **Queued transcripts say why they wait.** A queued transcript used to read "Queued · waiting for power or network" whatever the cause, including when the phone had power and Wi-Fi and was simply preparing another transcript first ([#299](https://github.com/andrepaim/distillpod/issues/299)). It now names the reason: after another transcript, waiting for a charger, battery low, waiting for Wi-Fi, offline, or Android blocked the start. Transcripts are still prepared one at a time, but one you ask for with **Prepare transcript** now goes ahead of the automatic ones for episodes you play.
- **Transcripts no longer pause with "Tap Resume" when power or Wi-Fi returns.** A transcript that waited for a charger or a network starts again in the background, where Android 12 and later refuses the notification that used to go with it. Earlier versions retried five times and then paused with "Android could not start transcription. Tap Resume to continue from saved chunks." ([#301](https://github.com/andrepaim/distillpod/issues/301)). The transcript now continues without the notification, one two-minute window at a time. Transcripts an earlier version paused with that message resume the next time DistillPod starts. A transcript you paused yourself stays paused.
- **"Only transcribe while charging" applies to transcripts already queued.** Switching it on or off used to affect only transcripts queued afterwards. A window already running finishes first.
- **Background downloads no longer pause with "tap Resume".** An episode or model download that starts while DistillPod is in the background (a feed refresh, show automation, a retry) was refused the same notification, retried five times and paused with "Android blocked the background download. Open DistillPod and tap Resume." ([#292](https://github.com/andrepaim/distillpod/issues/292)). It now downloads without the notification. Downloads an earlier version paused with that message resume by themselves. See the limit below for downloads that take longer than one background run.
- **Diagnostics uploads no longer stall for days.** With cloud diagnostics on, one phone delivered its reports one to two days late, in bursts, because the uploader waited up to five hours after a failed attempt and sent only part of the backlog each time ([#300](https://github.com/andrepaim/distillpod/issues/300)). It now sends the whole backlog in one run, waits at most 15 minutes after a failure, and sets aside a report the server keeps rejecting instead of blocking the ones behind it. Settings › Diagnostics shows the age of the oldest pending report and whether uploads are failing. With diagnostics off, nothing changes.

Install the signed APK over the existing app; do not uninstall first. This personal alpha keeps application ID `dev.distillpod.android` and the existing signing identity, and raises the version code to **61**. Database schema, backup file format, diagnostics journal format and Firebase rules/protocol are unchanged from 0.36.0-alpha.1. Downgrading the APK is not supported.

**Known limits:**

- **A long background download can wait until you open DistillPod.** A background download gets about ten minutes from Android. One that needs longer, or whose process Android ends in between, no longer fails or pauses: it stays queued with the part already downloaded. On the Galaxy S22 it then did not continue by itself, because the phone blocks the network of an idle app and does not start the job that would lift the block. It continued as soon as the app was opened. [#292](https://github.com/andrepaim/distillpod/issues/292) stays open for this.
- **No notification for work Android refused.** A transcript window or download that continues this way shows no notification. Progress in the app is unchanged.
- **Background transcription is slower and can stall for a while.** On the Galaxy S22 with the Tiny model a two-minute window took about a minute. Android can hold the next window for a few minutes, and after it ended the app's process it took 17 minutes to start it again. The transcript stayed queued throughout and was never paused.
- **Requested-first order is not kept everywhere.** It lasts until DistillPod restarts and does not apply to windows Android runs in the background; every queued transcript still runs.
- **Prepare transcript still obeys "Only transcribe while charging".** A transcript you ask for while unplugged waits for a charger and says so.
- **Not checked on a phone:** the Base model, transcripts an earlier version paused (tests only), and a second phone model. The upload fix is verified by tests; Sentry will show whether the affected phone delivers on time on this version.
- **Still open from earlier releases:** the limits listed in the [0.36.0-alpha.1](https://github.com/andrepaim/distillpod/releases/tag/v0.36.0-alpha.1) notes and earlier, including the Android Auto scrolling change not yet tried in a car.

**Validation:**

- **Hosted CI:** [#302](https://github.com/andrepaim/distillpod/pull/302), [#303](https://github.com/andrepaim/distillpod/pull/303), [#296](https://github.com/andrepaim/distillpod/pull/296) and [#304](https://github.com/andrepaim/distillpod/pull/304) each passed full CI: builds, unit and Robolectric tests, lint, Firebase rules, native checks and isolated emulator acceptance.
- **Phone (Galaxy S22, Android 16):** checked with separately installed test builds of the same code, not with this APK. The phone stayed on USB, so "unplugged" was simulated.
  - Transcripts: a transcript waiting for a charger finished in the background after power returned, with the phone locked and every notification start refused. The charging switch rescheduled queued transcripts in both directions. A paused transcript stayed paused through ten minutes on the charger and a restart. After the process was ended mid-window, transcription continued from the saved windows.
  - Downloads: background downloads of 60 MB and 795 MB completed. Pause held through a restart. A download paused by an earlier version resumed by itself. Opening the app continued a download that was waiting. The first test build failed two of these cases; the fix for that is included, and those two cases now wait as described under known limits.
- **Publication:** the release workflow separately reruns full validation, release lint/assembly and signing. The downloaded assets are then checked for checksums, source identity, package/version, non-debuggable state, retained certificate and alignment.
