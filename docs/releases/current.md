DistillPod 0.23.0-alpha.1 adds clearer queue controls, protects chosen queue orders from older pending writes, and recovers transcription when Android temporarily refuses foreground startup.

- **Reorder the whole queue:** see every item in its actual playback order, including the current episode, with labeled move-up/down controls and correct end boundaries. Rapid edits are handled in tap order, and controller events refresh the screen.
- **Clear and stop deliberately:** Clear queue and stop playback asks for confirmation. Cancel and Back leave playback unchanged, and an externally changed queue dismisses an outdated confirmation. Confirming stops playback and removes every queue item while retaining downloaded files and listening progress. Adding an item afterward does not automatically start playback.
- **Keep the queue you chose:** an explicit other-phone queue choice is ordered with pending local playback writes so an older snapshot cannot overwrite it. Current playback and progress are preserved, later explicit local edits take precedence, and stale restoration notifications cannot bring back a cleared queue. A failed player application no longer leaves its import marker suppressing a subsequent matching local edit.
- **Recover transcription startup:** Android foreground-start rejection keeps the transcript revision and saved chunks intact and retries with a bounded budget and exponential backoff. After five rejected startup attempts, the transcript pauses with a Resume action. Returning to the app recovers queued work when the activity is resumed; explicit pauses and replacement revisions remain protected from late cancelled attempts.
- **More reliable acceptance checks:** the automated Android suite now synchronizes permission-dialog input, Compose work and document-picker handoff, observes the real service queue, and retains failure evidence. These test improvements are not claims that previously unconfirmed production crashes were fixed.

Install the signed APK as an update **without uninstalling**. Version code **41** supersedes code 40 and retains the application ID and signing identity. Database schema 11, portable backup schema 7, Firebase protocol/rules and sync scope are unchanged. Older backups remain importable; new exports still require an app supporting schema 7. Paid content sync stays disabled. Voice preview and its full available listened-transcript behavior remain enabled with the existing setup, API-credit and context-readiness limitations. The corresponding GPL source archive, component manifest and notices accompany the APK.

**Known alpha limitations:** queue persistence remains asynchronous and is not guaranteed across abrupt process destruction before a pending write completes. Cloud-choice tests establish local conflict resolution and ordering, not live-account delivery or every possible device/network condition. The affected published versions of the reproduced queue race were not established. Android may still delay or reject transcription; retries follow WorkManager constraints and scheduling rather than a promised wall-clock deadline. Physical startup tests injected the denial, so they do not establish reproduction of a spontaneous OEM restriction, long-running inference or battery behavior. Existing voice readiness issue [#57](https://github.com/andrepaim/distillpod/issues/57), storage/diagnostics limits and YouTube restrictions remain; unmerged issue fixes and show-organization changes are not included.
