# Privacy and data handling

DistillPod keeps its library, queue, listening position, transcripts, saved excerpts and generated text in its private Android storage. ChatGPT credentials are encrypted with a key held by Android Keystore. Optional Firebase sign-in uses Firebase's SDK-managed app-private credential storage. Android application backup is disabled; neither provider's credentials enter library exports or library sync. This is a personal-alpha implementation; the repository's validation reports are not an independent security audit.

The published privacy policy, <https://andrepaim.github.io/distillpod/privacy.html>, opens in the browser from **Settings → About DistillPod → Privacy policy**. The same **Privacy policy** link sits next to each consent: connecting ChatGPT (Settings → ChatGPT), library sync (Settings → Sync) and diagnostics (Settings → Privacy & diagnostics). A build for Google Play has no library sync; see below.

## Current Spark-only deployment

The selected deployment has billing disabled. Sync is optional and requires a Firebase-configured build; ordinary source/debug builds have no production Firebase configuration. Google sign-in and feed review are required before library data is shared. Queue and portable preferences can synchronize through Firestore without enabling Cloud Storage. Transcripts and other finished text remain local; their experimental Storage adapter is disabled in builds. Automatic backup to a file you choose keeps transcripts and other text.

## Optional library sync

A build for Google Play has no library sync: it contains no Google sign-in, Firebase or Credential Manager code, carries no Firebase configuration and creates no account, so nothing of the library leaves the phone through sync and there is no cloud account to delete. Settings › Sync there offers automatic backup and restore only. See [builds without sync](android/subscription-sync.md#builds-without-sync). The rest of this section describes builds with sync, such as those published on GitHub.

Optional sync on `main` uses Google sign-in and Firestore storage for approved public subscriptions, listening progress, completion and saved moments. Cloud records include public feed/media addresses, feed-scoped episode identity and minimal display metadata, session/sequence identifiers, original positions/intervals, saved excerpts and completed moment quotes/insights with their model/source provenance. Record versions, operation receipts and ordered changes support retries and conflict review. The optional **Sync queue & preferences** scope adds queue and portable model/language/AI-model preferences. Full transcripts, episode analyses, conversation branches and explanations remain local: the experimental Cloud Storage adapter is disabled. Full RSS catalogues are refreshed from their source. Downloaded audio, models, unfinished computation and device policies remain local. Local job states, attempts and private file paths never enter sync.

On first connection, review which existing feeds to share. Existing and manually added sources are not uploaded automatically, because private RSS access tokens can be embedded in URL paths. Directory-result follows are treated as public sources. Password-bearing feed/media addresses and query-bearing feed addresses are excluded even when the source is selected. A media address is shared without its query string or fragment, which can carry signed-URL signatures, access tokens or tracking; YouTube videos, named by their query, and episodes whose GUID repeats a query-bearing address stay local. Episode IDs and media fingerprints are SHA-256 hashes that include the full address; they do not reveal signatures or random tokens but could confirm a guessed low-entropy query value. Oversized records stay local. Feed-sharing choices are local and must be reviewed again after a manual library restore; cloud-restored subscriptions retain the account's prior sharing decision.

Firebase Authentication receives the Google identity used to sign in. The library stays bound to its original Firebase user ID. A different account cannot adopt its outbox or upload its retained local data. Signing out pauses cloud work and keeps the offline library. Multiple local account profiles are not implemented yet. Unfollowing creates a cloud deletion marker while preserving local episode data; this does not erase historical cloud changes. The app cannot delete the sync account or its cloud records yet, because the deployed rules let no client delete them; deletion is a request by email to `andrepaim@gmail.com` from the account used for sync, handled within 30 days by deleting the Authentication user and every record under that account, as the [deletion page](https://andrepaim.github.io/distillpod/delete-account.html) describes. See [deleting a sync account](android/subscription-sync.md#deleting-a-sync-account). In-app erasure and independent dated cloud recovery are later milestones.

Cloud records are protected by per-user security rules and the provider's transport/storage encryption. This is not end-to-end encryption; the project administrator can access stored data. The selected Firestore database is in São Paulo. The inactive Storage experiment is not part of the enabled sync scope. Sync uses bounded work and retries, with foreground/network opportunities and periodic recovery. Android idle and force-stop can defer work; reopening the app resumes it.

## Telemetry status

Optional cloud diagnostics use Sentry with a device-local, default-off consent setting, bounded offline storage and allowlisted technical events. See [cloud diagnostics](android/cloud-diagnostics.md) for collected fields, delivery limits and validation evidence. Firebase Analytics, Crashlytics and Performance collection remain disabled. Enabling library sync does not opt into diagnostics. Configured S22 log and handled-error delivery have been verified; native crash reporting is not included.

## Network requests

Podcast directory searches send the query to Apple’s iTunes podcast directory. Typing in Search first looks through your own shows, episodes, transcripts and saved moments on the phone; that library search sends nothing and is not added to search history. The directory is queried only when you submit the search. Following/refreshing a feed, loading its artwork and streaming/downloading an episode contact the corresponding hosts. Refreshing a YouTube channel or playlist also reads YouTube’s public feed for it, and opening an older video without a date or description looks up that video on YouTube. A build for Google Play has no YouTube sources and makes none of these YouTube requests; see [videocasts](android/videocasts.md#builds-without-youtube-sources). Model downloads contact their configured upstream host. These services can observe the requests made to them.

Transcript preparation starts automatically when an episode plays unless **Settings → Transcript preparation → Transcribe when playing** is disabled. It can fetch publisher transcripts and download episode audio under the existing network and power policies. Model downloads remain explicit. This device-specific setting does not enable online transcript lookup or upload audio for transcription. Disabling it prevents new automatic requests; already queued work can be paused through the transcript controls.

Optional existing-transcript lookup sends the episode title to PodcastTranscript.ai for approved public sources. It defaults to off, never submits audio or creates a cloud transcription job, and does not share the feed/enclosure URL, listening progress, saved moments or credentials. The provider can observe the query and network address. Already downloaded text remains readable when lookup is disabled. Consent and lookup cooldowns stay on this installation. See [the lookup design](android/online-transcripts.md).

The update check asks GitHub's public Releases API once a day whether a newer DistillPod release exists, and reads that release's small build record. It sends no account, library or device data; GitHub can observe the network address and time. It is on by default and can be turned off in **Settings → About DistillPod → Check for updates**; debug builds never check on their own. Only builds distributed from GitHub contain it: a build for Google Play has no update check and never contacts GitHub, because Play delivers its updates. Downloading an update opens the APK link in your browser. See [the update check](android/app-updates.md).

Whisper transcription runs locally on the phone. Requested AI operations send selected transcript context to the connected provider, using the connected account's access and allowance. Episode audio is not uploaded for cloud transcription. Interest-based suggestions send followed-show titles only when that option is selected; suggestions are initiated explicitly.

## Backups and exports

Library backups contain readable personal library data: subscription and episode metadata, progress, queue, transcripts, saved moments and stored generated text, plus language/model choices. Drive backup uses a file chosen once in Android’s document picker and is updated daily by a background job when the library changed; the selected provider manages cloud sync. Managed backups are ZIP histories containing readable library data, social-post cover thumbnails and images from earlier infographic posts, with no passphrase encryption. Image-bearing snapshots use a bounded binary wrapper; older JSON snapshots remain readable. Persistent access to the user-selected file is stored only on that installation. Verified recovery copies stay in private app storage. They exclude account credentials, downloaded audio, model binaries and device-private file paths. OPML contains subscription titles and feed addresses. Choose destinations carefully and share exports only deliberately.

Do not include personal backups, feeds containing access tokens, recordings, account data or private screenshots in issue reports. A minimal reproduction on a development emulator is preferable. Repeated AI requests may consume additional plan allowance.

### Reporting an AI result

Each screen that shows text written by the model has **Report this result**: a saved moment's takeaway and quote (**More actions**), episode insights (summary, chapters and suggested ad ranges), each Ask this episode answer, Explain this idea explanations, share posts (the post's **⋮** menu), Find new voices suggestions and the voice preview's finished spoken answer. A report is an email to the public contact address, `andrepaim@gmail.com`, sent only by you from your own email app. Before that app opens, DistillPod shows the exact message, and you can untick **Include the result text** to remove the reported text. The message contains the feature name, the model name when the result recorded one, the app version and, unless removed, the reported result text. It never contains other transcript text, your question, episode audio, account identity, tokens or installation identifiers. DistillPod itself sends nothing. On a phone without an email app, the address and message are shown for you to copy instead.

### Social post drafts

Posts, their cover thumbnails and original source snapshots remain on the device and are included in manual library backups. Existing library sync does not upload posts. Creating a post makes one request through the connected ChatGPT account containing the saved excerpt, the saved quote and insight when present, and the show and episode titles. **Change** also sends the current card, caption and your instruction. If the answer fails the app's checks, one repair request follows containing the previous answer and the validation message. No web search is made and no image is generated by a model. The provider can observe those requests. During generation the app fetches the podcast artwork from the podcast's own image host and stores a small 320×320 cover thumbnail with the post. Cards are drawn locally from the stored text with bundled fonts and are not stored as images. Switching style or look, reopening, copying or sharing a completed result does not make an AI request. Generation uses the connected account’s allowance; interrupted work requires an explicit retry. Posts from the earlier infographic format keep their stored images and source references.

Sharing exports the card image (or an earlier post's text or image) to another app; **Share** also places the caption on the Android clipboard. Image exports in the app cache are available through temporary URI grants and cleaned after seven days on a subsequent export; images explicitly saved to Pictures/DistillPod remain until deleted by the user. Draft deletion does not recall exports or content already shared externally.


When the optional voice preview is enabled, the owner can save an OpenAI project API key on the phone. A separate Android Keystore key encrypts this credential in app-private preferences. It is excluded from library backups, portable settings and sync, and can be replaced or removed in Settings → Voice. Voice sends the spoken question and selected transcript context directly to OpenAI using this key; there is no voice credential broker or Google sign-in requirement. Raw recordings are transient. The most recent answer and content-free usage diagnostics remain in process memory. See [voice preview](android/voice-mode.md) for validation limits.

Optional usage statistics have their own default-off control in Settings → Diagnostics. Approved feature/action counts and trigger categories contain no podcast content. Diagnostic operation summaries persist privately for up to 72 hours (maximum 500 revisions) and are excluded from backups/sync. Revocation purges pending envelopes; provider retention governs reports already delivered. See [reliability analytics](android/reliability-analytics.md).
